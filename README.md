# API-based Declaration Parser (new_parser)

## Описание

Это API-версия парсера деклараций, которая вместо Selenium использует прямые обращения к API ФСА для получения данных о декларациях.

## Отличия от старого парсера

| Параметр | Старый (Selenium) | Новый (API) |
|----------|-------------------|------------|
| Метод получения данных | Парсинг DOM через Selenium | Прямые вызовы API |
| Время работы | Медленно (ждёт загрузки страниц) | Быстро (прямые API запросы) |
| Нужен браузер | Да, Chrome driver | Нет |
| Зависит от структуры страницы | Да, селекторы часто ломаются | Нет, использует стабильный API |
| Excel вывод | Совместим | Совместим (идентичные колонки) |

## Использование

### 1. Установка зависимостей

```bash
pip install -r new_parser/req.txt
```

Или вручную:
```bash
pip install openpyxl requests customtkinter
```

### 2. Запуск GUI

```bash
python new_parser/gui.py
```

### 3. Использование

1. **Bearer-токен**: вставьте токен из DevTools (Network → Headers → Authorization)
2. **Файл Excel**: выберите файл, в который будут записаны результаты
3. **Список ID**: выберите текстовый файл с идентификаторами деклараций (по одному на строку)
4. **Старт**: нажмите кнопку "Старт" для запуска парсинга

## Как получить токен

1. Откройте https://pub.fsa.gov.ru/rds/declaration
2. Откройте DevTools (F12 → Network)
3. Обновите страницу (Ctrl+R)
4. Найдите запрос к `/api/v1/rds/common/declarations/get`
5. В заголовках (Headers) найдите `Authorization: Bearer ...`
6. Скопируйте токен (часть после `Bearer `)

## Как подготовить список ID

Создайте текстовый файл `fsa_declaration_ids.txt` с одним идентификатором на строку:

```
18565969
18565970
18565971
```

Получить ID можно:
- Из URL декларации: `https://pub.fsa.gov.ru/rds/declaration/view/{ID}/common`
- Используя script `deklar_id` для сбора ID по техрегламентам

## Процесс работы

1. Парсер читает список ID из файла
2. Для каждого ID делает запрос к API ФСА
3. Извлекает поля: номер, статус, схема, тип, заявитель, ИНН, производитель, адрес, продукт, стандарты
4. Записывает значения в Excel в те же колонки, что и старый парсер
5. Обновляет прогресс в UI
6. После завершения сохраняет файл

## Записываемые колонки

| Колонка | Значение |
|---------|----------|
| C | Номер декларации |
| D | Схема (например, "1д") |
| E | Статус |
| F | Заявитель |
| G | ИНН |
| H | Производитель |
| I | Адрес |
| J | Наименование продукта |
| K | Документ |
| L | Стандарты |
| Q | Тип объекта декларирования |
| R | Тип декларации |
| P | ID (внутренний) |

## Отладка

Если парсер не работает:

1. **Токен не валиден**: возьмите свежий токен из DevTools
2. **API не отвечает**: проверьте интернет соединение
3. **ID не найден в API**: возможно, ID был удалён или недоступен

## Сравнение с deklar_id

Проект `deklar_id` собирает ID по техрегламентам через API.
Проект `new_parser` (этот) берёт готовый список ID и заполняет Excel данными по каждому ID.

Типичный workflow:
```
deklar_id (собрать ID по ТР) → файл с ID → new_parser (заполнить данные в Excel)
```

## Лицензия

Используется в образовательных целях для работы с открытым реестром ФСА.
